Attestations

An attestation is a claim someone made about a node: that they downloaded a file and got these hashes, that they read through a table's records and they looked right, or that a system scored this well on a benchmark. They are how the data in this catalog gets checked by people other than whoever wrote the code that loads it.

Anybody can submit one anonymously. To make an attestation count as coming from you, register an identity (a key pair) and your submissions are signed with it. Attestations are held by a small server at attest.ir-datasets.com and appear in the graph as attest: nodes, with an attest:attestation edge from the node each one is about. A node with attestations gets a Verification card summarizing them.

Submit with the ir_datasets attest command or from Python (below); see its README for the details.

The kinds of attestation

HashAttestation

files and tables

Hashes someone computed. For a file, the hashes of its bytes, and where they were downloaded from (nothing, for a copy obtained some other way). For a table, a hash over its parsed records, so it holds across re-encodings of the same data; hash_version says how it was computed, so the method can change later without invalidating old attestations.

{"kind": "hash", "subject": "irds:antique-test-queries.txt",
 "attested_at": "2026-10-28T12:00:00Z",
 "source": "https://ciir.cs.umass.edu/…",
 "hashes": ["md5:…", "sha256:…"]}
Submit
ir_datasets attest hash irds:antique-test-queries.txt   # a file
ir_datasets attest hash irds:antique-test-queries       # a table

VisualAttestation

tables

A person's report that they read through a sample of a table's records and either they looked right, or they found problems (garbled text, misaligned ids, truncated documents…). It needs a person to have actually looked, so it must be signed: an anonymous “a human checked this” means little.

{"kind": "visual", "subject": "irds:antique-test-queries",
 "attested_at": "2026-10-28T12:00:00Z",
 "verdict": "ok",                // or "issues"
 "notes": "texts look right",
 "sample": ["3990512", "714612"]}   // ids inspected
Submit
ir_datasets attest visual irds:antique-test-queries \
    --verdict ok --sample 3990512 714612 --notes "texts look right"

EvaluationAttestation

benchmarks

Scores a system obtained on a benchmark. Run the same well-known system (BM25, say) on a benchmark and compare with what others got: a benchmark whose scores don't reproduce usually has a problem with its documents, queries or judgments.

{"kind": "evaluation", "subject": "irds:antique-test",
 "attested_at": "2026-10-28T12:00:00Z",
 "system": "Terrier BM25",
 "measures": {"nDCG@10": 0.32, "MAP": 0.20}}
Submit
ir_datasets attest evaluation irds:antique-test \
    --system "Terrier BM25" -m nDCG@10=0.32 -m MAP=0.20

IdentityAttestation

people

A username bound to a public key, vouched for by its own signature. Registering generates an Ed25519 key pair, sends the public half, and keeps the private half on your machine (~/.ir_datasets/attest/identity.json). From then on ir_datasets attest signs what you submit. Usernames are first come, first served.

{"kind": "identity", "attested_at": "2026-10-28T12:00:00Z",
 "username": "alice", "public_key": "…"}
Register
ir_datasets attest register alice

From Python

from ir_datasets.v2 import attest

attest.attest_hash('irds:antique-test-queries')
attest.attest_evaluation('irds:antique-test', 'Terrier BM25', {'nDCG@10': 0.32},
                         identity=attest.Identity.load())   # omit identity to submit anonymously
attest.for_node('irds:antique-test')                     # everything attested about a node

How the Verification card decides

Attestations are taken at face value; nothing here proves the data is right, only how well the attestations agree. A node's card shows one of these:

{% for key, (label, badge, explanation) in statuses.items() %}
{{ label }} {{ explanation }}
{% endfor %}
  • Hashes are grouped by what they hash (a file's bytes, or a table's content at one hash_version) and by algorithm; two attestations that hash the same thing with the same algorithm should give the same digest.
  • A file's hash is also checked against the hash the node itself declares, for any algorithm they have in common.
  • A single attestation, even a signed one, never reaches Verified on its own unless it matches the declared hash.
  • A signature says who made an attestation, checked by the server when it was received. It is not an endorsement.
